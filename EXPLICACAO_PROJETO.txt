A-Maze-ing — Explicação completa (até agora)

Objetivo do projeto
O programa gera um labirinto 2D, guarda a representação em texto e desenha o resultado numa janela usando MLX (uma biblioteca gráfica simples). Também consegue reabrir um labirinto salvo e mostrar o caminho padrão quando pedido.

Estrutura do workspace
- a_maze_ing.py: lógica principal de geração, desenho e execução.
- config.txt: configuração (largura, altura, entrada, saída, etc.) usada ao iniciar.
- maze.txt: ficheiro gerado com a representação do labirinto (hex) e metadados.
- mlx/: biblioteca gráfica em Python (wrapper de MLX) usada para abrir janela e desenhar pixels.

Visão geral do fluxo
1) Lê configurações de ficheiro (se fornecido) ou usa valores padrão.
2) Cria um MazeGenerator para construir o labirinto.
3) Gera o labirinto via algoritmo DFS (depth-first) ou reconstrói a partir de maze.txt.
4) Escreve maze.txt com a grelha e metadados (entrada, saída e caminho).
5) Abre janela MLX e desenha o labirinto.
6) Escuta teclas para regenerar, alternar caminho, trocar cor e sair.

Como o labirinto é representado (dados)
O labirinto é um dicionário: self.maze[(x, y)] aponta para um bloco com paredes e flags.
Cada célula tem:
- west, south, east, north: 1 (parede) ou 0 (passagem)
- visited: usado na geração
- 42: marca o desenho especial “42” no meio do labirinto

Codificação em hex (bit_math)
Cada célula é codificada num dígito hexadecimal (0–F). A fórmula é:
- west*8 + south*4 + east*2 + north*1
Isto gera um valor 0–15, convertido para um caractere hex.
Esse texto vai para maze.txt.

Decodificação (reverse_bit_math)
Lê maze.txt, transforma cada hex novamente nas 4 paredes e reconstrói:
- paredes da célula
- visited = True
Depois lê as linhas extra do ficheiro:
- linha 1: ENTRY
- linha 2: EXIT
- linha 3: instruções do caminho (NSEW) para reconstruir default_path

Geração do labirinto (MazeGenerator)
O algoritmo usado é DFS (depth-first search) com backtracking:
- Começa na ENTRY.
- Em cada passo, escolhe aleatoriamente um vizinho não visitado.
- Remove a parede entre as células.
- Marca como visitado e continua.
- Se ficar sem opções, volta atrás (pilha hasVisited).
Durante o percurso até encontrar a EXIT, é gravado default_path, que é o caminho “padrão”.

“42” no centro
O método fourty_two marca um padrão de coordenadas relativas ao centro do labirinto.
Essas células recebem a flag “42” = True.
No desenho, essas células são pintadas com uma cor específica para formar “42”.

Como o MLX está a ser usado (explicação simples)
MLX é uma biblioteca gráfica muito básica. O uso aqui é direto:
- Mlx() cria o objeto da biblioteca.
- mlx_init() inicializa o contexto gráfico.
- mlx_new_window() cria uma janela com a largura/altura calculadas.
- mlx_pixel_put() desenha um pixel na janela.
- mlx_string_put() escreve texto na janela.
- mlx_key_hook() registra uma função para lidar com teclas.
- mlx_hook() trata o evento de fechar janela.
- mlx_loop() entra no loop principal de eventos (a janela “fica viva”).

Como o labirinto é desenhado na janela
Cada célula do grid é desenhada “pixel a pixel”:
- Cada parede (north, south, east, west) desenha uma faixa de pixels.
- ENTRY e EXIT são desenhadas como um bloco central.
- Células “42” são desenhadas com outra cor.
- Se solution_visible estiver True, o default_path é desenhado por cima.

Teclas disponíveis
No handler gere_key:
- Tecla 1: gera um novo labirinto e redesenha.
- Tecla 2: alterna a visibilidade do caminho (solution_visible).
- Tecla 3: muda a paleta de cores.
- Tecla 4 ou ESC: fecha a janela.

Ficheiro maze.txt (formato)
1) Grelha de hex (WIDTH x HEIGHT), uma linha por linha.
2) Linha em branco.
3) ENTRY (ex: 0,0)
4) EXIT (ex: 29,29)
5) Linha com instruções do caminho (ex: ENNSSW...)

Classes principais
- ImgData: estrutura simples para dados de imagem (ainda não usada).
- XVar: guarda referências globais da MLX, janela e maze atual.
- Solver: esboço de solver (marcado como “busted”).
- MazeGenerator: geração, representação e desenho do labirinto.

Limitações atuais
- Solver não está funcional.
- reverse_bit_math depende de maze.txt e assume formato correto.
- A janela não se adapta dinamicamente ao tamanho do ecrã.
- O “42” está fixo no centro sem validações de colisão com ENTRY/EXIT.

Resumo
O projeto gera um labirinto, guarda-o em ficheiro texto e desenha o resultado num window MLX. A lógica é centrada numa estrutura de dados simples (paredes como bits), um algoritmo DFS para geração e uma camada gráfica que pinta cada célula e parede na janela.
